# Project preferences

## Device-first persistence

- Save answers, edits and completed results on the device first. Keep answering, navigation and result viewing independent of cloud uploads.
- Open cached device data immediately. Upload in the background, retry after reconnecting, and preserve newer device changes when older cloud responses arrive.
- Keep cloud-saving status and session-recovery choices out of normal practice flows.

## Product UI copy

- Reuse the existing practice and timed-test question UI for every question flow, including coaching. Do not create a separate question layout; adapt the shared components and keep session storage and scoring separate.

- Keep screens concise. The user dislikes decorative subtitles, taglines, and repeated explanations beneath headings, cards, or buttons.
- Do not add filler such as "Fresh questions, work at your own pace", "A clear next step, built around you", "Your preparation, personalised", or "Section snapshot - first attempts across the app".
- Prefer a clear heading, the actual information, and the action. Do not fill empty space with motivational slogans or generic reassurance.
- Supporting text should add information needed to understand a result, choose an action, or understand a consequence: for example a recommendation's specific reason, an exam date, a score's meaning, or a deletion warning. Keep it brief and avoid repeating nearby labels.
- Put scoring methodology and detailed explanations in the relevant detail view or help control when they are needed; do not scatter explanatory captions across the main screen.
- Apply this preference to future work throughout this project, including new features and revisions.
